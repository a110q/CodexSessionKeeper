# codex_会话管理操作手册

本文档用于后续开发交接，包含产品说明、目录结构、本地运行、macOS 构建、Windows 10 便携版 exe 构建、发布验证和常见问题。

## 1. 产品定位

`codex_会话管理` 是一个本地 Codex 会话管理工具，用来管理、备份、恢复和清理用户机器上的 `~/.codex` 会话数据。

核心目标：

- 频繁切换 Codex 账号、模型供应商或配置后，帮助用户找回丢失的会话。
- 支持只恢复对话，不覆盖当前账号、登录态和模型供应商配置。
- 支持从快照恢复单个会话。
- 支持删除单个或批量删除会话。
- 支持删除单个或批量删除快照。
- macOS App 和 Windows 10 便携 exe 版本保持功能与界面结构一致。

数据默认保存在本机，不上传网络：

```text
Codex 数据目录：~/.codex
快照库目录：~/.codex-session-vault/snapshots
Windows 设置文件：~/.codex-session-vault/settings.json
```

## 6. Windows Electron 本地开发

进入 Windows Electron 工程：

```bash
cd /Users/awk/lqf/code/codex_huihuaguanli/windows/codex_session_manager_electron
```

安装依赖：

```bash
npm install
```

本机启动 Electron 调试：

```bash
npm start
```

如果提示 Electron 未正确安装，重新安装 Electron：

```bash
rm -rf node_modules package-lock.json
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install
```

Windows 版关键文件：

- `src/main.js`：读取 `~/.codex`、创建快照、恢复快照、删除会话、批量删除、SQLite 合并。
- `src/preload.js`：把主进程能力暴露给前端。
- `src/renderer.js`：会话列表、快照列表、批量选择、弹窗确认、恢复操作。
- `src/index.html`：界面结构。
- `src/styles.css`：对齐 macOS 版的浅色分栏界面。

Windows 快照策略：

- 创建快照时优先保存并清洗 `state_5.sqlite`。
- 如果 `state_5.sqlite` 报 `database disk image is malformed`、`file is not a database` 或其他不可读错误，主进程会移除快照里的坏数据库，降级创建文件型快照。
- 文件型快照仍保留 `history.jsonl`、`session_index.jsonl`、`sessions`、`archived_sessions`，依赖 jsonl 扫描恢复会话。
- 恢复前、删除前自动保护点也使用同样降级策略，避免因为保护点创建失败导致主操作无法继续。
- 复制 `sessions`、`archived_sessions` 等目录时必须逐文件容错。Windows 上单个 jsonl 文件可能因为 Codex、杀毒软件或同步盘锁定而 `EPERM lstat`，不能让整个快照失败。

## 9. 用户操作说明

会话管理：

1. 打开 app 后进入“会话管理”。
2. 搜索框可按标题、目录、模型、ID 过滤。
3. 单击会话选中。
4. 双击会话查看对话记录。
5. 右键会话可从最近快照恢复指定会话。
6. 勾选多个会话后，可点击“删除选中”批量删除。

快照恢复：

1. 切到“快照恢复”。
2. 可输入备注后点击“创建快照”。
3. 选择某个快照后，右侧显示快照详情。
4. 优先使用“只恢复对话”，它不会覆盖当前账号、登录态和模型供应商配置。
5. 如果只要恢复某一条会话，在“单个会话恢复”里搜索并恢复选中会话。
6. 只有明确要回滚账号、登录态和 `config.toml` 时，才使用“完整恢复”。
7. 勾选多个快照后，可点击“删除选中”批量删除。

自动找回：

1. 顶部“打开时自动找回”默认关闭。
2. 用户手动开启后，app 启动时会检测当前会话数量和最新有效快照。
3. 如果发现当前会话比快照少，会弹窗询问是否恢复。
4. 确认后只合并恢复对话，不覆盖当前账号和模型配置。

## 10. 本地增量备份

应用启动后会自动扫描 `~/.codex/sessions` 和 `~/.codex/archived_sessions`，并把新增 `.jsonl` 完整行追加保存到：

```text
~/.codex-session-vault/incremental-backups
```

常用排查：

1. 查看界面里的“本地增量备份”状态。
2. 点击或手动打开备份目录。
3. 检查 `status.json` 的 `lastBackupAt`、`sessionCount`、`lastError`。
4. 检查 `manifest.json` 的会话索引和 `cursors.sqlite` 的读取游标。

第一阶段恢复会生成文件型恢复包，不强行重建 `state_5.sqlite`。恢复后如果 Codex 已打开，请重启 Codex。

## 11. 数据安全规则

开发和维护时必须遵守：

- 不要默认覆盖用户当前 `auth.json` 和 `config.toml`。
- 恢复对话默认走“只恢复对话”。
- 完整恢复必须有明确确认。
- 删除会话前必须创建保护快照。
- 批量删除会话只创建一次删除前保护快照。
- 删除快照不应该影响当前 `~/.codex`。
- 不要把用户会话、账号信息上传网络。

## 12. 常见问题

Windows 解压后中文乱码：

- 交付 `codex_session_manager_win10_portable.zip`。
- 包内文件夹和 exe 名都是英文，避免乱码。
- 不要交付旧 PowerShell 版本作为主版本。

Windows exe 打不开：

- 确认解压完整，不要直接在 zip 预览里运行。
- 确认 `resources/app/node_modules/sql.js/dist/sql-wasm.wasm` 存在。
- 重新打包并检查 zip 内容。

Electron 安装失败：

```bash
cd /Users/awk/lqf/code/codex_huihuaguanli/windows/codex_session_manager_electron
rm -rf node_modules package-lock.json
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install
```

macOS 空白区域异常：

- 优先检查 SwiftUI 横向 `HStack` 里的 `Divider()`。
- 横向操作栏里的 `Divider()` 要限制高度，例如 `.frame(height: 22)`。

会话恢复后 Codex 没显示：

- 让用户退出并重新打开 Codex。
- 确认恢复的是“只恢复对话”还是“完整恢复”。
- 检查快照里是否包含 `state_5.sqlite` 和 `sessions`。

Windows 创建快照时报 `database disk image is malformed`：

- 这是 SQLite 层错误，通常是 Codex 正在写 `state_5.sqlite`、WAL 还没合并，或数据库文件已经损坏。
- `v1.0.10` 起创建快照不会因此失败，会降级创建文件型快照。
- 文件型快照没有 `state_5.sqlite` 也可以恢复会话文件；如果需要完整 SQLite 索引，先退出 Codex 再创建一次手动快照。
- 维护时不要把这个错误直接抛给 renderer；应在 `src/main.js` 内保留降级和 warning 回传。

Windows 创建快照时报 `EPERM: operation not permitted, lstat ...jsonl`：

- 这是某个会话 jsonl 文件被锁定、权限不足或被安全软件拦截。
- `v1.0.11` 起创建快照会跳过这个单文件并继续复制其他会话。
- warning 中会记录被跳过文件的相对路径，用户可退出 Codex 或关闭同步/杀毒占用后再创建一次补充快照。
- 维护时不要恢复整目录 `fs.cpSync` 复制，应该保留 `copyEntryIntoSnapshot` 的逐文件容错逻辑。

## 13. 后续维护建议

- mac 和 Windows 新增功能时，先改 mac 数据模型和 UI，再同步 Windows IPC 与 renderer。
- 两端按钮文案、确认弹窗、功能入口尽量保持一致。
- 每次发布都重新跑发布前验证清单。
- 不要在仓库里提交 `.build`、`dist`、`node_modules`。
- Windows 构建产物只放到 Downloads 或 release 附件，不放源码目录。
