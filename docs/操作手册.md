# codex_会话管理操作手册

本文档用于员工使用、开发交接和公司内网发布。`1.1.0` 采用员工确认式更新：应用可以提示新版，但不会强制下载或安装。

## 1. 员工首次安装

1. 只从公司 NAS 的员工下载目录取得 `1.1.0`。
2. macOS 解压 ZIP 后将 `codex_会话管理.app` 放入“应用程序”；Windows 运行 Setup EXE 完成当前用户安装。
3. 当前内部版本没有 Apple/Windows 商业证书。首次系统警告只按公司管理员提供的说明确认；来源、文件名或版本不一致时停止安装。
4. 首次打开后确认“本地增量备份”状态正常，再进行快照或恢复操作。

## 2. 员工更新流程

- 发现新版：选择“稍后提醒”不会下载；选择“立即更新”才开始下载。
- 下载完成：选择“稍后重启”可以继续工作。
- 完成安装：选择“重启并更新”后，应用先等待备份停止写入，最多等待 5 秒。仍有写入时会取消重启并恢复备份轮询。
- 内网之外：定时检查静默跳过，不影响软件使用；手动检查会提示暂时无法连接。
- 更新完成：新版本首次启动显示一次“已更新到 X.Y.Z”。

更新不会清空 `~/.codex`、快照、增量备份游标或应用设置。macOS 使用 Sparkle 验证 ZIP，Windows 会在下载后再次核对 Setup EXE 的版本、文件名、大小和 SHA-256。

## 3. 会话和快照操作

会话管理：

1. 在“会话管理”中按标题、目录、模型或 ID 搜索。
2. 单击查看预览，双击打开完整对话。
3. 可打开原始会话文件或在文件夹中定位。
4. 删除单条或批量会话前，工具会先创建保护快照。

快照恢复：

1. 切换到“快照恢复”，可添加备注后创建手动快照。
2. 优先选择“只恢复对话”，它不会覆盖当前 `auth.json`、`config.toml` 或登录态。
3. 可恢复单条、勾选的多条或快照中的全部对话。
4. 只有明确需要回滚账号和配置时才使用“完整恢复”。
5. 外部附件恢复到 `~/.codex/recovered_attachments/<快照 ID>/<会话 ID>/`，不会写回不可信绝对路径。

自动找回默认关闭。员工开启后，应用启动时才会比较当前会话与最新保护点，并在恢复前询问。

## 4. 本地增量备份与恢复

应用扫描以下目录：

```text
~/.codex/sessions
~/.codex/archived_sessions
```

增量数据写入：

```text
~/.codex-session-vault/incremental-backups
```

排查时查看 `status.json`、`manifest.json` 和 `cursors.sqlite`。恢复缺失会话时：

1. 关闭 Codex。
2. 打开“快照恢复”，来源切换到“备份恢复”。
3. 选择状态为“可恢复”的一条或多条会话。
4. 等待保护点和恢复完成，随后重启 Codex。

恢复只补回缺失会话，不覆盖已存在会话、账号或配置。SQLite 索引无法写入时，JSONL 文件仍会保留并显示警告。

## 5. 项目结构

```text
Sources/CodexSessionVault/Update/       # macOS 更新协调器、Sparkle 驱动和弹窗
Sources/CodexSessionVaultCore/Update/   # 公共清单验证与检查状态机
windows/codex_session_manager_electron/
  src/update/                           # Windows 签名更新服务和状态文件
  src/main.js                           # 文件、SQLite、受信 IPC 和更新接入
  src/preload.js                        # 最小权限 Electron API
  src/renderer.js                       # Windows 界面和更新弹窗
scripts/update/                         # 密钥、清单、验证和原子发布工具
deploy/nas/                             # 只读 Nginx/Compose 配置
```

## 6. 开发与自动化测试

macOS 需要 macOS 14+、Swift 6 工具链和 Xcode Command Line Tools：

```bash
swift build
swift test
```

Windows Electron 单元测试可在发布 Mac 运行：

```bash
cd windows/codex_session_manager_electron
npm ci
npm test
```

发布工具：

```bash
node --test scripts/update/*.test.mjs
bash -n scripts/update/publish-release.sh
```

## 7. 构建候选包

macOS：

```bash
APP_VERSION=1.0.99 APP_BUILD=10099 scripts/build_app.sh
APP_VERSION=1.1.0 APP_BUILD=10100 scripts/build_app.sh
codesign --verify --deep --strict dist/codex_会话管理.app
```

Windows x64：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_windows_installer.ps1 -Version 1.0.99 -Build 10099
powershell -ExecutionPolicy Bypass -File scripts\build_windows_installer.ps1 -Version 1.1.0 -Build 10100
```

旧便携构建已经停用。任何自动更新测试只能使用 NSIS 安装版。

## 8. 管理员签名和发布

1. 发布 Mac 钥匙串分别保存公共清单 Ed25519 私钥和 Sparkle 私钥；仓库只保存公钥。
2. 在用户确认外置加密卷已挂载后，运行 `scripts/update/backup-update-keys.sh` 创建口令加密备份。不得备份到仓库或 NAS。
3. 使用 `build-release-manifest.mjs` 组装候选，使用 `verify-release-directory.mjs` 独立验证。
4. 完成双平台标准用户 `1.0.99 → 1.1.0` 演练。
5. NAS 部署或发布是外部状态变更，必须再次取得明确批准。
6. `publish-release.sh` 固定最后发布 `release.json`，版本化产物不同哈希时拒绝覆盖。

完整命令见 [NAS 内网更新部署与发布](NAS内网更新部署与发布.md)。

## 9. 发布前验收

两平台均需确认：

- 内网启动后按预期出现提示。
- “稍后提醒”没有下载产物。
- “立即更新”显示递增进度。
- “稍后重启”后应用仍可用。
- “重启并更新”先排空备份再重启到 `1.1.0`。
- 完成提示只出现一次。
- 会话、快照、设置、增量游标和 NAS 备份身份不变。
- 离开内网后应用正常且定时检查静默。
- 被篡改的清单和安装包无法安装。

Windows 还需验证：不请求管理员权限、“应用和功能”条目、`latest.yml` 一致、篡改 Setup EXE 被删除、可正常卸载。macOS 需在 `/Applications` 和用户 `Applications` 各演练一次。

## 11. 常见问题

`database disk image is malformed`：通常是 Codex 正在写 `state_5.sqlite` 或数据库已损坏。工具会尽量创建文件型快照；先退出 Codex 再创建一次手动快照可提高 SQLite 索引完整性。

`EPERM: operation not permitted, lstat`：通常是会话文件被 Codex、安全软件或同步工具占用。工具会跳过单个不可读文件并继续处理其他会话，员工可解除占用后补做快照。

恢复后 Codex 未显示会话：重启 Codex，检查 JSONL 是否恢复成功，并查看 SQLite warning。数据库索引失败不等于会话文件丢失。

## 12. 历史包应急规则

历史 macOS/Windows 包只用于管理员在隔离环境读取旧快照、导出重要会话或诊断兼容问题，不得重新放入员工下载目录或自动更新目录。Windows 历史便携包必须完整解压，不能单独复制 EXE。应急恢复完成后迁移到正式 `1.1.0+` 安装版。
