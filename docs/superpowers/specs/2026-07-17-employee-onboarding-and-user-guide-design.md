# 员工首次使用引导与使用说明设计

日期：2026-07-17
状态：已由用户确认

## 背景

Codex 会话管理将面向约 130 名公司员工内部使用。软件已经能够固定识别公司 NAS、让员工从实时目录中选择部门和姓名，并执行会话增量备份、回读校验及恢复。但现有详细说明主要位于代码仓库，普通员工下载软件后无法方便地找到；首次配置页面也没有完整覆盖安装拦截、备份状态、异常处理和恢复流程。

本设计同时提供：

1. NAS 下载目录中的一份跨平台图文安装说明。
2. macOS、Windows 软件内部的首次使用引导和长期可访问的帮助入口。

## 目标

- 没有参与开发的员工可以独立完成安装、NAS 配置和首次备份。
- 员工只能选择 NAS 中实际存在的部门和姓名，不能输入任意路径。
- 只有真实备份状态达到“备份已验证”，首次引导才算完成。
- NAS 断开、验证失败或首次备份中断时，员工能看到明确的下一步操作。
- 员工可以随时从主页面重新打开帮助，不必寻找代码仓库文档。
- macOS、Windows 使用相同术语解释相同状态。

## 非目标

- 不增加账号系统、在线帮助中心、视频教程或远程服务。
- 不改变 NAS 目录、manifest、verification、cursor、IPC 或恢复数据格式。
- 不允许用户手工输入服务器、共享盘或文件系统路径。
- 不在本轮实现自动更新；后续可以增加只读的版本提示。
- 不通过引导绕过 NAS 安全验证或备份完整性检查。
- 不在本设计中修改“打开时自动找回”功能；制作最终截图前应先修复其偏好每次启动被重置的问题，或从说明中暂时移除该功能。

## 发布目录

管理员在 NAS 上维护以下只读下载目录：

```text
Codex会话管理/
├── macOS/
│   └── Codex会话管理-macOS-arm64.dmg
├── Windows/
│   └── Codex会话管理-Windows-x64.exe
├── Codex会话管理-安装与使用说明.pdf
└── 安装包校验信息.txt
```

普通员工对该目录只有读取权限。`安装包校验信息.txt` 记录版本、发布日期和两个安装包的 SHA-256，仅供管理员排查，员工正常安装时不需要操作。

正式发布使用明确版本目录，同时把当前员工版本复制到稳定的 `latest/` 目录；不依赖 SMB 符号链接。上传完成后，管理员先验证 SHA-256，再开放员工读取。

## 首次使用流程

### 第一步：检测公司 NAS

软件自动检查固定服务器 `192.168.10.99` 和固定共享盘“文件中转站”。页面显示服务器、共享盘和真实检测状态，但不提供可编辑路径。

若 NAS 未连接：

- macOS 显示如何在 Finder 中连接公司服务器。
- Windows 显示如何在资源管理器中连接公司共享盘。
- 提供“重新检测”按钮。
- 不允许进入部门和姓名确认步骤。

### 第二步：确认备份身份

部门和姓名均来自 NAS 当前直接子目录列表：

- 先选择部门，再读取该部门下的姓名。
- 部门改变时必须清空并重新选择姓名。
- 显示逻辑预览，例如“运营部 / 陈超 / 当前电脑”。
- 不向员工显示或允许编辑底层绝对路径。

### 第三步：验证并执行首次备份

点击“验证并开始备份”后，界面只展示后端真实阶段：

1. 正在验证目录。
2. 正在执行首次备份。
3. 正在从 NAS 回读校验。
4. 备份已验证。

界面显示已发现、已完成和待处理的会话数量。首次备份尚未完成时明确提示不要退出；如果用户仍尝试退出，继续沿用现有退出保护确认。

### 完成条件与恢复

只有现有 NAS 运行时进入 `running`，且配置与当前设备标记仍然有效时，才写入本地 `onboardingVersion = 1`。

- `unconfigured`、`disconnected`、`validating`、`seeding`、`verifying`、`pending` 或 `error` 都不能标记完成。
- 中途退出后，重新启动根据真实 `NASSetupSnapshot` 恢复到正确页面，不重复已经验证的身份选择。
- 配置缺失、损坏、设备标记变化或目标重新验证失败时，即使存在完成标记也重新进入安全配置。
- 引导完成标记只控制是否展示教程，不可作为备份成功的依据。

旧版本升级兼容：如果本地已经存在配置和设备标记，软件不强迫员工重新选择身份，而是先验证现有目标。验证后进入 `running` 时静默写入 `onboardingVersion = 1`；断开或验证失败时展示对应状态和修复动作，不把老用户误判成从未配置的新用户。

## 软件内界面

### 首次引导

扩展现有 macOS `NASSetupView` 和 Windows NAS 设置区域，不再创建第二套配置流程。首次未配置时，引导不可关闭；已经配置的用户主动重新打开时可以关闭。

页面顶部显示三个固定步骤：

1. 连接公司 NAS
2. 选择部门和姓名
3. 完成首次备份

当前步骤根据真实运行状态高亮。界面避免复杂动画、浮层高亮和技术名词。

### 长期帮助入口

主页面右上角增加“使用帮助”，打开一个离线帮助面板。帮助包含四个主题：

1. 安装与首次启动
2. 备份状态说明
3. NAS 断开与异常处理
4. 会话恢复和更换电脑

帮助面板还显示软件版本，并提供：

- “重新检测 NAS”操作入口。
- “重新配置部门和姓名”操作入口。
- “打开恢复页面”操作入口。

这些入口调用现有受保护操作，不新增任意路径能力。

## 状态文案与动作

| 实际状态 | 员工文案 | 主要动作 |
|---|---|---|
| `unconfigured` | 尚未选择部门和姓名 | 开始配置 |
| `disconnected` | 未检测到公司 NAS | 查看连接方法、重新检测 |
| `validating` | 正在验证备份目录 | 等待 |
| `seeding` | 正在进行首次备份 | 查看进度、暂勿退出 |
| `verifying` | 正在确认 NAS 文件完整 | 等待 |
| `running` | 备份已验证 | 进入主页面 |
| `pending` | 有会话等待补传 | 保持 NAS 连接、立即重试 |
| `error` | 备份出现异常 | 查看简明原因、重试或联系管理员 |

所有页面统一使用“备份已验证”，不使用“上传完成”代替，因为上传后仍需回读校验。

错误信息分为两层：员工首先看到一句可执行说明；“查看详情”再显示底层错误。不得在主提示中展示 SQL、manifest、哈希分块或内部绝对路径。

## 外部 PDF

文件名固定为 `Codex会话管理-安装与使用说明.pdf`，总长度控制在 5 页以内：

1. 下载正确的 macOS 或 Windows 版本。
2. 安装与首次启动，包括 macOS Gatekeeper 和 Windows SmartScreen。
3. 连接 NAS，选择部门和姓名。
4. 识别“首次备份中”“正在校验”“备份已验证”和异常状态。
5. 新电脑恢复、NAS 断开、安全退出和重新配置。

PDF 使用最终发布构建的真实截图和红框标注，不包含真实员工会话正文、账号、令牌、内部数据库内容或可写共享凭据。封面显示适用软件版本和文档更新时间。

安装包按钮名称、状态术语和 PDF 必须与应用一致。界面文字变更时，发布检查必须重新确认 PDF，不允许长期保留失效截图。

## 内容与维护方式

- `docs/员工安装与使用说明.md` 作为 PDF 的受版本控制源文件。
- macOS 和 Windows 的简短帮助内容保留在各自应用资源中，使用同一份术语表。
- 增加轻量契约测试，确认两端都包含八个状态的统一中文名称、固定公司 NAS 名称和四个帮助主题。
- PDF 构建产物放入 `dist/`，不把二进制 PDF 当作业务源代码手工编辑。
- 每次发布由构建脚本生成或复制 PDF、安装包和校验信息到一个版本化交付目录。

## 安全与隐私

- 引导只消费现有经过校验的部门、姓名和状态数据。
- 不在 UI、日志或 PDF 中展示 NAS 凭据。
- 不提供任意路径输入、Finder/资源管理器目录选择或跳过目录验证的入口。
- 完成标记不能覆盖实际 NAS 状态；运行时状态始终优先。
- 下载目录应由管理员写入、员工只读。共享盘备份目录仍需依赖 NAS 回收站、快照和 ACL 提供服务端保护。

## 测试

### 自动化测试

macOS、Windows 分别覆盖：

- 未配置时首次引导必须出现且不能跳过。
- NAS 未连接时无法进入身份确认。
- 部门变化清空姓名。
- 只有 `running` 且设备标记有效时写入完成版本。
- 首次备份中退出后，从真实阶段恢复。
- 配置损坏、设备标记不匹配或重新验证失败时重新进入引导。
- 已完成用户升级后不重复弹出。
- 离线时仍能打开全部帮助主题。
- 帮助入口调用现有安全操作，不接收原始文件系统路径。
- 两端术语契约一致。

### 人工验收

- 一台全新 Apple Silicon Mac。
- 一台安装过旧版本的 Mac。
- 一台 Windows 10 或 Windows 11 电脑。
- NAS 未连接、连接失败和恢复连接。
- Gatekeeper 和 SmartScreen 的实际提示。
- 首次备份直到“备份已验证”。
- 全新电脑恢复会话。
- 软件退出、重启和登录后自动运行。
- PDF 截图、按钮名称和最终软件逐项一致。

至少邀请一名未参与开发的员工只依赖 PDF 和软件内提示完成验收。成功标准是该员工无需询问管理员即可完成安装和身份配置，能够确认备份已验证，并知道 NAS 断开后的处理方式和恢复入口。

## 发布顺序

1. 修复或隐藏与实际行为不一致的“打开时自动找回”说明。
2. 实现双端首次引导和帮助入口。
3. 完成自动化测试和双端构建。
4. 用最终构建截取匿名化截图并生成 PDF。
5. 由未参与开发的员工执行一次完整验收。
6. 生成 SHA-256，上传版本化交付目录。
7. 管理员验证下载目录只读后开放内测。

## 已确认决策

- 同时提供软件内引导和 NAS 下载目录说明。
- 采用关键路径三步引导，不制作完整功能巡游。
- 首次 NAS 安全配置不能跳过，普通帮助可以随时关闭。
- SHA-256 校验信息保留给管理员，不要求员工操作。
- 外部文档使用跨平台 PDF，控制在 5 页以内。
- 帮助内容离线可用，不引入网络服务或新账号系统。
