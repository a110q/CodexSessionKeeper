# Codex 会话管理桌面端 Aurora Glass UI 重设计

## 背景

当前应用已经完成一轮轻量化改版，但整体仍然建立在原有工具型布局之上，视觉气质还不够统一。用户希望进一步做一次“整体从 UI 上重新设计”，并明确要求：

- 整体更年轻化
- 更有科技感
- 颜色体系明显变化
- 仍要像成熟产品，而不是概念稿

在可视化评审中，用户最终选择了 `A1 · Spark` 方向：明亮 aurora 背景、玻璃卡片、偏强 electric blue 强调、整体更有未来感。

## 目标

将 macOS 桌面端界面整体升级为一套统一的 `Aurora Glass / Spark` 视觉系统。

具体目标：

- 用新的配色和材质语言重塑整个 app，而不是只修局部组件。
- 保持现有三栏工作流与功能路径不变。
- 明确主次操作层级，让界面既年轻又高效。
- 让 UI 在视觉上更像一个成熟的现代桌面产品。

## 非目标

- 不修改会话管理、快照恢复、恢复逻辑等业务能力。
- 不改变功能信息架构，不新增页面层级。
- 不改成深色主题主导的产品。
- 不引入高风险、强定制的非原生交互动画系统。

## 视觉方向

### 核心关键词

- Aurora
- Glass
- Electric
- Light
- Product-grade

### 视觉原则

- 背景有氛围，但内容必须清楚。
- 科技感来自秩序、层次、发光感和透明感，不来自花哨装饰。
- 蓝色是主强调色，但只出现在关键位置。
- 所有卡片、面板、标签、按钮要服从统一圆角和描边体系。

## 配色系统

### 基础背景

- 主背景：偏冷白的 aurora 渐变
- 辅助背景：极浅蓝 / 极浅青过渡
- 内容区底色：高透明白或低透明白蓝玻璃层

推荐倾向：

- 亮部：`#F8FBFF`
- 冷白蓝：`#EAF3FF`
- 冷白青：`#ECFBF7`

### 强调色

- 主强调色：electric blue
- hover / active 可使用更亮的蓝色变体
- 高风险操作继续使用淡红体系，与主蓝分开

推荐倾向：

- 主蓝：`#1677FF`
- 高亮蓝：`#3E9CFF`
- 危险色：柔和红，不使用刺眼纯红块

### 文本颜色

- 主标题：深墨蓝灰
- 次级说明：低对比冷灰
- 标签/辅助信息：更浅灰蓝

## 材质与表面语言

### 玻璃卡片

应用的主要容器统一使用轻玻璃化表面：

- 半透明白底
- 细白描边
- 轻阴影
- 大圆角

使用区域：

- 侧边栏状态卡
- 顶部设置块
- 列表工具区
- 详情主操作卡
- 指标卡

### 发光与高光

只用于少量关键位置：

- 主按钮
- 当前选中项
- 关键计数或当前激活操作

不能滥用到每个元素，否则会失去成熟感。

## 页面结构

保留三段式工作流，但重定义视觉职责：

- 左侧：导航与当前系统状态
- 中间：搜索、筛选、选择列表
- 右侧：详情、推荐操作、风险操作

## 详细设计

### 1. 顶部栏

目标：

- 更像产品头部，而不是默认控件条

设计要求：

- 左侧保留页面切换 segmented control
- `工作区` 标签保留，但弱化
- 右侧 `打开时自动找回` 作为次级设置块存在
- 设置块更紧凑、更细、更弱，不可抢主标题视觉
- 顶部整体使用更轻的间距和更清晰的边界线

### 2. 左侧导航栏

目标：

- 让导航面板从“功能栏”变成“产品侧边导航”

设计要求：

- 使用 aurora 风格浅色渐变背景
- 标题更像产品名，而不是大号工具标题
- 当前状态卡统一为玻璃信息卡
- 导航项选中态改为浅蓝高亮胶囊 / 光晕感
- 非选中态更轻、更系统化

### 3. 中间列表区

目标：

- 让列表区像现代内容浏览器

设计要求：

- 工具区继续拆成筛选层 + 批量操作层
- 主输入框和筛选控件统一风格
- 批量危险操作只在必要时出现
- 列表项更卡片化，但不能太厚重
- 选中项使用更明显的 electric blue 高亮
- 标签（如手动、系统自动、归档、缺文件）更细、更亮、更统一

### 4. 右侧详情区

目标：

- 让详情区成为页面视觉中心

设计要求：

- 大标题更有产品感
- 主操作卡更突出，使用最明显的 aurora/electric 蓝体系
- 次级按钮保持玻璃白风格
- 指标卡统一高度、圆角、描边和阴影
- 内容卡之间节奏更清晰，减少“堆一排卡”的感觉
- 高级恢复、删除等高风险区域独立收纳

### 5. 分栏与交互

目标：

- 保持可拖拽，但更高级、更自然

设计要求：

- 分栏拖拽热区保留
- 分隔视觉更细、更轻，但 hover / drag 时有明确反馈
- 不牺牲可用性换取极简外观

## 控件层级规则

- 主按钮：electric blue
- 次按钮：白色 / 玻璃白
- 危险按钮：淡红背景或描边，不与主蓝混用
- 输入框：浅玻璃输入面
- segmented control：更精致、更贴近高端桌面产品
- badge / tag：统一胶囊样式

## 必须保留的行为约束

- `打开时自动找回` 默认关闭
- 快照页不得再出现批量操作按钮重复
- 分栏必须易于拖拽
- 窄宽度下按钮不能截断

## 实现建议

优先采用现有 SwiftUI 结构上的视觉重构：

1. 先统一 app shell：背景、顶部栏、侧边栏
2. 再统一内容卡体系：PrimaryActionCard / DetailCard / MetricCard / 状态卡
3. 再统一列表与工具区：会话页、快照页
4. 最后做色彩和选中态精修

## 验证标准

完成后应满足：

- 整体配色与旧版有明显区别
- 用户一眼能感受到“年轻化 + 科技感”
- 主次操作比当前更清晰
- 三栏效率结构不被破坏
- 设置、列表、详情的视觉语言统一
