# codex_会话管理 — UI 与功能改进建议

> 评审范围：`README.md`、`docs/操作手册.md`、`Sources/CodexSessionVault/main.swift`（SwiftUI / macOS）、`windows/codex_session_manager_electron/src/*`（Electron / Windows）。
> 评审重点：**界面 UI 优先**，功能其次。建议按"高 / 中 / 低"标注优先级，便于排期。

---

## 1. 总体印象

| 维度 | 现状 | 评价 |
|---|---|---|
| 信息架构 | 顶部 Tab（会话 / 快照） + 左列表 + 右详情 | 清晰，符合直觉 |
| 视觉风格 | macOS：Aurora 渐变 + 玻璃卡片；Windows：纯白扁平 | **两端风格断裂**，品牌一致性不足 |
| 操作密度 | 单页面装下了搜索 / 过滤 / 批量 / 创建 / 详情 | 控件密度偏高，新手第一眼会"看不到主操作" |
| 反馈机制 | Busy 遮罩 + Toast + 状态栏 | 完整，但样式略灰、不够"安心" |
| 暗色模式 | 两端均未实现 | 缺失（macOS 用户期望，Windows 11 用户也期望） |
| 可访问性 | 无 ARIA、无快捷键提示、无对比度审视 | 缺失 |

**一句话结论：**功能已经齐全且稳健，"差的是把现有功能呈现得更清爽、让用户一眼知道下一步该按什么"。

## 2. 高优先级 UI 建议（建议本次迭代就改）

### 2.1 Windows 端：补回"当前 Codex 状态"卡片 〔高〕

`windows/.../src/index.html` 第 12–33 行写了完整的 `aside.sidebar` 包含 brand-block / state-card / side-nav，但 `styles.css` 第 64 行 `.sidebar { display: none; }` 把它整条隐藏了。
macOS 端却保留了同样信息（`AppSidebar` + `CurrentStateCard`）。结果：

- **品牌识别（左上角 logo + 标题）丢失。**
- 用户切换账号 / 供应商前，**看不到当前是哪个 provider / model / account**，而这正是这个工具最核心的卖点。

**建议改法：**

1. 改成"窄边栏 + 主区"两列布局（边栏宽 240–260px，可折叠）：
   ```
   ┌──────────┬──────────────────────────────────┐
   │ 🛡 logo  │   topbar（保留 Tab 切换）         │
   │ codex_会 │----------------------------------│
   │ 话管理   │                                  │
   │          │     左列表 │ 右详情              │
   │ 状态卡片 │                                  │
   │ ───────  │                                  │
   │ 导航     │                                  │
   └──────────┴──────────────────────────────────┘
   ```
2. 把"打开时自动找回"开关从 topbar 移到边栏底部的"设置区"，因为这是偏好而不是高频动作。
3. topbar 只留：Tab 切换 + 刷新 + 打开目录，视觉负担减半。
4. 当窗口 < 1080px 时边栏自动折叠为 56px 图标条（hover 弹出气泡），保留响应式。

> 同步把 `index.html` 里 `.brand-mark` 的字母 "C" 换成 `Assets/CodexSessionVaultIcon.png` 缩略 PNG，提升精致度。

---

### 2.2 统一两端视觉语言 〔高〕

| 元素 | macOS 现状 | Windows 现状 | 建议统一为 |
|---|---|---|---|
| 背景 | Aurora 渐变 + 径向光 | `#f5f5f5` 纯灰 | **两端都用浅渐变**（Windows 可用 CSS `linear-gradient` + 轻噪点滤镜模拟），但渐变强度减半，避免喧宾夺主 |
| 卡片 | 白色 0.68 透明 + 1px 白描边 + 22px 圆角 | 灰底 `#f7f7f7` + 12px 圆角 | 统一 **16px 圆角**、**白底 0.85 alpha**、**1px `rgba(0,0,0,0.06)` 描边** |
| 主操作按钮 | `.borderedProminent`（蓝） | `.primary-button` `#007aff` | 统一颜色，但**增加 hover/press 阴影**：`box-shadow: 0 6px 14px rgba(0,122,255,.22)` |
| 危险按钮 | `role: .destructive` 红 | `#c0362c` | Windows 端改为 `#dc2626`（更接近 macOS 系统红），避免偏暗 |
| 角色徽章颜色 | user=蓝 / assistant=绿 | 同 | ✅ 已一致 |
| 字体 | 系统 | Segoe UI / 雅黑 | Windows 增加 `"PingFang SC"` 作为中文 fallback（在 Windows 中文环境用雅黑没问题，但混合英文 + 数字时雅黑的等宽数字不好看，建议数字处用 `font-variant-numeric: tabular-nums`，**styles.css 第 312 行已有局部应用，扩展到所有 meta 行**） |

---

### 2.3 列表行的信息层级再做一遍 〔高〕

当前会话行（`SessionRow` / `.session-row`）的结构是：

```
☐ [标题（粗）]    [归档标签] [缺文件标签]
  provider / model · source
  2026-05-19 13:22
```

问题：
- **三行都是浅灰色 + 12px**，重要信息（更新时间、模型）几乎一样灰，**视觉锚点只剩标题**，扫读体验差。
- 没有未读 / 新增 / 异常的视觉钩子。

**建议改法：**

```
☐ ●  [标题]                                   2 小时前
     gpt-5-codex · ~/codex-project           45 messages · 1.2 MB
```

- 左侧加 4px 圆点（`●`）：蓝色=今天更新，灰色=超过 7 天，红色边缘=`!session.existsOnDisk`。
- 右上角用**相对时间**（"2 小时前"），完整时间放 tooltip。
- 右下角放消息数 + 文件大小，**而不是把 provider / model 当主信息**——provider 在状态卡片已经显示，行内换成更"个性化"的元数据更有用。
- 标签从右上角移到行右侧，跟时间同列对齐。

---

### 2.4 详情面板增加"会话预览" 〔高〕

当前右侧详情只有元数据 + 三个按钮，看对话必须双击打开 modal。
**建议：** 把"对话预览"做成详情面板的默认内容（前 20 条消息，每条 200 字），点"查看完整对话"再开 modal 全屏。

收益：
- 用户选中会话后，**3 秒就能判断这是不是要找的会话**，而不是双击 → 看一眼 → 关闭 → 再选一个。
- 减少模态弹窗的认知中断。

---

### 2.5 暗色模式（Dark Mode） 〔高〕

macOS 用户大部分系统跟随暗色；Windows 11 也有原生暗色。

- **macOS（SwiftUI）：** 把所有硬编码 `Color(red:..., green:..., blue:...)` 替换为语义色：`Color.primary` / `Color.secondary` / `.background` / `.tint`，并用 `@Environment(\.colorScheme)` 区分两套渐变。Aurora 在暗色下改成深紫 + 深青的低饱和版本。
- **Windows（CSS）：**  把 `:root` 里的 12 个色变量复制一份到 `@media (prefers-color-scheme: dark)`，预计 30 行 CSS 改完。

## 3. 中优先级 UI 建议

### 3.1 顶部 topbar 操作密度过高 〔中〕

Windows 端 topbar 同时塞了：功能 Tab、自动找回开关、刷新、打开目录菜单。
建议：

- "自动找回"挪到边栏 → 见 2.1。
- "打开目录"挪到 macOS 那种 Menu 按钮（`...`），下拉两项。
- 保留：左侧 Tab、右侧"刷新（图标按钮）+ 设置（齿轮图标）"，干净。

### 3.2 过滤卡（filter-card）样式 〔中〕

现在过滤卡是 `background: rgba(120,120,128,0.08)` 的色块，**和列表行 hover 颜色相同**（`.session-row:hover` 也是 `rgba(120,120,128,0.08)`），导致鼠标 hover 一条时背景没有对比度变化。

- 把 filter-card 改为 `rgba(0,0,0,0.03)` + `border-radius: 12px` + `inset 0 0 0 1px rgba(0,0,0,0.04)`，浅 0.5 个调子。
- 或者干脆不用色块，改成"分组 + 12px gap + 上下 12px padding"，更现代。

### 3.3 批量操作条 〔中〕

当前批量操作按钮（全选可见 / 清空选择 / 删除选中）和搜索框混在一起，**只有选中后才显示后两个**——但用户第一次进来根本不知道有"批量"这件事。

建议：

- 选中条改成**列表顶部的浮动条**（已经有 `position: sticky` 的潜质），选中时滑入，未选中时折叠成"批量操作 ▾"小按钮。
- 选中条上同时显示选中数量、估算占用磁盘、最近操作时间等。

### 3.4 ConversationViewer modal 〔中〕

当前：
- 用 `92px` 固定列宽放 role badge（`role-badge`），左侧浪费 92px 空间，但 role 文本只有 "用户" / "助手"（两字符）。
- 消息卡片用 `var(--card-bg)` 灰底，**用户和助手颜色相同**，长对话扫读时分不清谁说的。

建议：
- role 区域压成 `48px`（badge + 时间叠加在一起）。
- **气泡风格**：用户消息靠右、淡蓝底；助手靠左、白底带细描边。或者保持卡片式但**助手左侧加 3px 绿色 accent bar，用户加 3px 蓝色**。
- 给消息卡片加 `tabular-nums` + 等宽代码块识别（`<pre>` / 三反引号）。Codex 对话里常出现代码，目前 `white-space: pre-wrap` 会保留换行但不高亮，建议引入轻量的 markdown 渲染（不用引入 marked.js，自己写 ≤80 行的最小实现即可，只处理 \`\`\` 代码块和 \`inline\` 代码）。

### 3.5 BusyOverlay 〔中〕

两端都是"不确定进度条"循环动画。如果后端能给出"已处理 / 总数"，建议改成**确定进度条**（已经有 `model.busyProgress` 字段 → main.swift 第 3997 行），Windows 端 `index.html` 第 162 行的 `.busy-progress span` 也接了，但 renderer 是否真的赋宽度 % 需要核对。

- 在 busy card 上**显示当前处理的文件名 / 第几个 / 共几个**，让用户对"还要等多久"有概念。
- "请耐心等待"这种 footnote 文案显得不自信，改成 "**正在写入快照，请勿关闭应用**" 这种动作导向的提示。

### 3.6 macOS Aurora 背景节制使用 〔中〕

`auroraBackground` 用了 3 层渐变 + 2 个径向光 + 玻璃卡片 + 1px 白描边，**层数偏多**，在低端 Mac 上会有明显的合成开销，长列表滚动有时会跳帧。

建议：
- 列表区域用纯色 / 极浅渐变作为底，**只在 topbar 和详情卡片背后保留 aurora**。
- `RoundedRectangle(... .continuous)` 的 `1px` 白描边在 retina 上确实漂亮，但和 `.shadow(... radius: 18)` 叠 4 次（macOS 端有），可以合并为 1 次外阴影 + 1 次 inset 高光。

## 5. 功能层面建议

UI 之外，列出影响"用户用得爽不爽"的功能项，按优先级排序：

### 5.1 〔高〕会话内容全文搜索

现在搜索只覆盖 标题 / 目录 / 模型 / 来源 / ID / 路径（README 第 23 行），**找不到"我之前那个讨论 SwiftUI 渲染的对话"**。

实现思路：
- 在快照库目录维护一份 SQLite FTS5 索引（`sessions_fts`），首次启动建库，会话扫描时增量更新。
- 搜索框加一个 "🔍 全文" 切换开关，开启后用 FTS5 `MATCH`，**关键词高亮**用 `snippet()`。
- 大约 200–400 行代码（Swift 用 `SQLite.swift`，Electron 已经在用 `sql.js` 直接复用）。

收益：这是这类工具的**核心价值跨越点**——从"管理工具"变成"知识库"。

### 5.2 〔高〕快照保留策略可视化 + 自动清理

`README` 第 130 行提到"系统快照有保留数量限制"，但用户不知道当前阈值、不知道哪些会被自动清掉。

- 在边栏增加"快照库"卡片：总占用、快照数、最早一份的时间。
- 设置面板里暴露：手动快照保留数（默认 ∞）/ 系统快照保留数（默认 N）/ 单个快照大小上限 / 自动清理 30 天前。
- 当占用超过阈值时，状态卡片用橙色提示"快照库较大"。

### 5.3 〔高〕会话导出（Markdown / JSON）

ConversationViewer 已经能渲染消息，**只差一个"导出"按钮**：

- 单会话：导出 `.md`（带 frontmatter：title / id / model / provider / created / updated）。
- 多选会话：批量导出到一个目录，或打包 `.zip`。
- 导出在分享给同事、贴到博客、训练自己的 LLM 提示库时都有用。

### 5.4 〔中〕两个快照之间的"差异查看"

切换账号前后各打了一次快照，用户经常想知道**期间产生 / 丢失了哪些会话**。

- 在快照详情面板加"和另一个快照对比"，下拉选一个快照，列出 added / removed / modified。
- 实现量小：两个快照 session_index 求差集。

### 5.5 〔中〕收藏 / 置顶 / 标签

会话量上来后，用户会想"标记几个最常回看的"。

- 列表行加一个 ★ 图标按钮，星标会话在过滤器里有"仅星标"开关。
- 进阶：会话上可以打 1–N 个 tag（项目名、客户名），tag 通过本地 JSON 存（不污染 Codex 原始数据）。

### 5.6 〔中〕"快速恢复"工作流

切换账号是这个工具的**核心使用时刻**，但目前流程是：

1. 用户切换账号前，主动想到要打快照（容易忘）。
2. 切换完发现对话没了，打开本工具。
3. 进入快照 Tab，找到对的那份，点"只恢复对话"。

建议增加一个**入口级"快照前/快照后"按钮组**（边栏顶部）：

- **"切换账号前"** → 一键创建带 `pre-switch-2026-05-19-13:22` 命名的快照，弹个 toast 提示"已就绪，可以去切账号了"。
- **"切换账号后未恢复"** → 检测 sessions 数量骤降，主动提示"上次快照里有 N 条新会话，要恢复吗？"

### 5.7 〔中〕首次启动引导

工具的概念（快照 / 只恢复对话 / 完整恢复 / 自动找回）有学习成本。
建议：

- 第一次启动放一个 3 步 onboarding：① 这工具能做什么 ② 推荐流程（切账号前先打快照） ③ 自动找回开关默认关闭，需要的时候再开。
- README 里的"推荐使用方式"段落本身就是好材料，可以直接搬过来。

### 5.8 〔低〕系统托盘 / 后台守护

- macOS：menu bar extra，常驻显示当前 provider / model；点击可一键"打快照"。
- Windows：托盘图标，同上。
- 默认关闭，避免用户觉得是"后台软件"。

### 5.9 〔低〕国际化（i18n）

当前全中文。如果想推海外用户，可以预留 i18n 文案表（哪怕只有 zh + en），不增加实质工作量但门槛感降低。

### 5.10 〔低〕可观测性

- 应用内一个"操作日志"页（最近 100 条 创建/恢复/删除 操作），用户怀疑"我刚才点了啥"时能查。
- 这个对你后续排查用户问题也有用。

## 6. 我会优先做的 5 件事（如果排时间）

1. **Windows 端补回边栏 + 状态卡片**（2.1）→ 拿回品牌识别和核心卖点的视觉表达。
2. **统一两端视觉语言、引入暗色模式**（2.2 + 2.5）→ 提升整体质感最快的两件事。
3. **会话行信息层级重排 + 详情面板加预览**（2.3 + 2.4）→ 用户用得最频繁的操作路径，体感最明显。
4. **会话内容全文搜索**（5.1）→ 让工具从"管理"升级到"找回"，留存关键。
5. **"切换账号前"一键快照入口**（5.6）→ 把核心使用时刻产品化，减少用户漏打快照的痛点。

## 7. 验收建议

每条改动落地后，建议自己跑一遍这 5 个场景，看主观体感是否变好：

- **场景 A**：第一次打开 app，30 秒内能不能说出"这工具是干嘛的、我现在该按哪个按钮"。
- **场景 B**：有 200 条会话，找到上周和某个客户讨论 X 主题的那条，耗时多少。
- **场景 C**：切换 provider 前后完整跑一遍快照 → 切换 → 恢复，全程几个点击、几次需要看文档。
- **场景 D**：故意删一个会话，再用快照恢复，是否清晰可逆。
- **场景 E**：暗色模式下，连续看 5 分钟对话，眼睛是否舒服。
